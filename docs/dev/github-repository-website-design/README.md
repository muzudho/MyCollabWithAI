# GitHub リポジトリーの Web サイト設計


## リポジトリーのトップページの README.md の構成

３行ぐらいで、このプロジェクトの概要を具体例を交えて説明する。  

例：  

```plaintext
ニコニコ動画等での生配信を想定して、配信しやすく、視聴者も楽しめやすく、  
20分ぐらいで遊び終わるゲームを作ることを目指しています。  
シミュレーション（ストラテジー）ゲームです。  
```

まず、開発中の画面のスクリーンショットを１枚貼る。  
`開発中の画面です。（ver.0.1.0）` みたいなキャプションを付ける。  

次に、環境スペックを簡単に書く。  

```plaintext
Windows 11 想定
```

以下の具体的な４人の対象読者を想定する。  

* `灰谷さん` - 一般。このプロジェクトに興味はないが関心はある人。
* `赤川さん` - ユーザー。説明書も読まずに、ゲームをダウンロードして遊びたい人
* `緑山さん` - リサーチャー。説明書をしっかり読んで、ゲームの仕組みを理解したい人
* `青田さん` - デベロッパー。ゲームの開発に興味がある人

そこでまず、中見出しを４つに分ける。

* `一般_このプロジェクトに興味はないが関心はある人`
* `ユーザー_すぐ遊びたい人` 
* `リサーチャー_しっかり理解したい人`
* `デベロッパー_開発に興味がある人`

> AIエージェント向け情報：
>
> それぞれの節に、現在の README.md の内容を、ふさわしい読者に向けて、  
> ドキュメントを分類してください。  
> フォルダーは以下のものを用意したので、うまく整理に使ってください。  

* `docs/pub/` - 一般向けのドキュメントを入れる。広告や謝罪文、注意喚起など。
* `docs/user/` - ユーザー向けのドキュメントを入れる
* `docs/ref/` - リサーチャー向けのドキュメントを入れる
* `docs/dev/` - デベロッパー向けのドキュメントを入れる
