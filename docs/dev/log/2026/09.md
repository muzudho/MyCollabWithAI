# 2026年9月 開発日誌

## 9月27日

AI と共同作業するためのリポジトリーを立ち上げた。MonoGame の .NET 9 プロジェクトを置き、README から作成したスクリプトの説明へたどれるようにした。ファイル整理のスクリプトは `scripts/File` 以下に用途別のフォルダーを作って配置した。

最初に、PNG ファイルを作成年月で整理する `TransferPng` を作成した。`FileList.ps1` が同じフォルダー内の PNG を CSV に一覧化し、`FileTransfer.ps1` が指定した CSV に従って `YYYY-MM` フォルダーへ移動する。移動先に同名ファイルがあれば上書きせず、元のファイルを残す。

続いて、バックアップ内の重複ファイルを整理する `RemoveDuplicatedOldFile` を作成した。探索時は、まず拡張子を含むファイル名とサイズが一致するものに候補を絞り、その候補だけ MD5 を計算する。同名・同サイズ・同ハッシュのファイルが複数ある場合に、パスと作成日時を `FileHashList.csv` へ出力する。CSV は UTF-8（BOM なし）、CRLF 改行にした。

移動スクリプトは、各グループで作成日時が最も新しい 1 件を残し、古いファイルを元の相対パスを保って `TrashCan` へ移す。実行前に内容を説明して `[Y/n]` で確認し、衝突時は移動せずログに残す。移動によって空になった元のフォルダーは、対象ルートを残して削除する。

NAS の大量のファイルで試す過程では、PowerShell の実行ポリシー、探索の待ち時間、長いパスが課題になった。`OpenPowerShellHere.cmd` を追加して、そのセッションだけスクリプトを実行できるようにした。探索と移動には約 4 秒間隔の進捗表示を入れ、長いパスは拡張パス形式で扱うように変更した。読めないファイルがある場合は `FileHashList.errors.log` に記録し、その CSV を使った移動は止める。

Windows PowerShell 5.1 のテストでは、重複抽出、CSV の文字コードと改行、移動先の衝突、実行中止、空フォルダー削除、長いパスを確認した。NAS 上の全ファイルを対象にした最終結果は未確認。大量のバックアップでは対象フォルダーを小さく分けて実行し、エラーログの有無と CSV の内容を確認してから移動する。

Visual Studio の個人設定やビルド出力を `.gitignore` に追加した。すでに Git が追跡している `bin/` と `obj/` のファイルは、この変更だけでは追跡対象から外れない。
